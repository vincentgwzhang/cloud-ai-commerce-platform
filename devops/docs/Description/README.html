Cloud AI Commerce Platform

A production-style microservices commerce platform built to demonstrate end-to-end backend, cloud-native, and AI engineering: event-driven services, GitOps delivery, observability, and a Retrieval-Augmented Generation (RAG) assistant.

Personal project. Everything below is implemented and runnable on a single laptop (Minikube).

What it is

Six independently deployable Spring Boot services behind an API gateway, talking over REST and Kafka, deployed to Kubernetes three different ways (kubectl, Helm, and ArgoCD GitOps), with full metrics/tracing and an OpenAI-powered RAG service.

Service Port Responsibility
Auth 8080 Stateless RS256 JWT auth (login / refresh rotation / validate)
Product 8081 Catalog with Redis cache-aside + lock
Inventory 8082 Reservations, anti-overselling, idempotency, optimistic locking
Order 8083 Order orchestration via Kafka Saga choreography
AI 8084 Chat, conversation memory, and Product RAG (OpenAI + ChromaDB)
Gateway 8088 Single entry point (Spring Cloud Gateway)

Tech stack

  • Language / framework: Java 25, Spring Boot 4.0.6, Spring Cloud 2025.1.0
  • Data: MySQL 8, Redis 7, Apache Kafka 4.3 (KRaft, no ZooKeeper)
  • Security: OAuth2 Resource Server, RS256 JWT, RSA key pair
  • AI: OpenAI (text-embedding-3-small + gpt-4o-mini), ChromaDB vector store, RAG
  • Cloud-native: Docker, Minikube, Kubernetes, Helm, Argo CD (GitOps), Bitnami Sealed Secrets
  • Observability: Micrometer → Prometheus, Grafana dashboards, OpenTelemetry tracing, MDC correlation IDs
  • Quality: JUnit, Testcontainers, JaCoCo coverage gates (80%, Auth 85%)

Engineering highlights

  • Three delivery paths, all idempotent — the same platform deploys via raw kubectl, via a single Helm chart, or via Argo CD pulling from Git. See Kubectl, Helm, Argo CD.
  • GitOps with safe secrets — Argo CD syncs the Helm chart from Git; the OpenAI API key is committed as Sealed Secrets ciphertext (safe in a public repo) and decrypted in-cluster.
  • Event-driven Saga — Order ↔ Inventory coordinate asynchronously over Kafka with dead-letter handling and idempotent consumers.
  • RAG done with clean boundaries — product data stays in Product service; the AI service keeps an eventually-consistent vector replica synced via Kafka events. Embedding / vector-store / LLM are swappable behind interfaces.
  • Observability by default — every service exposes Prometheus metrics and trace-correlated logs.
