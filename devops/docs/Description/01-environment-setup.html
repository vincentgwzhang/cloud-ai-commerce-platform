01 — Environment Setup

How to get the whole platform running on a single machine. There are three ways to run it; this page covers the shared prerequisites and the fastest happy path.

Prerequisites

Tool Version Why
JDK 25 Build/run the services
Maven 3.9+ Multi-module build
Docker recent Kafka, Chroma, Prometheus/Grafana, image builds
Minikube recent Local Kubernetes (scenarios 2 & 3)
kubectl / Helm recent Deploy to the cluster
MySQL 8 / Redis 7 — Host-managed data stores

Host services you manage

The deploy scripts never start or stop your databases — you run them yourself:

  • MySQL :3306 — database commerce_platform, user vincent
  • Redis :6379

Apply the schema (idempotent, includes sample users + the AI tables):

mysql -h 127.0.0.1 -u vincent -p commerce_platform < devops/db/init.sql

Sample users (password 123456): vincent (USER), admin (ADMIN), tester (USER).

JWT keys (one command)

All services share one RSA key pair for RS256 JWT:

./devops/script/local-dev-setup.sh   # generates devops/data/keys/{private,public}.pem if missing

Three ways to run

Goal Entry point Doc
Run on host (IntelliJ / mvn) docker compose ... up -d + run apps [Kubectl/Helm pages + repo devops/README.md]

GitOps with Argo CD Argo CD syncs the chart from Git 10 — Argo CD

Fastest local happy path

# infra
docker compose -f devops/script/docker-compose-app.yml up -d                   # Kafka
docker compose -f devops/script/docker-compose-observability-local.yml up -d   # Prometheus + Grafana + Chroma

# run services (separate terminals), profile "local"
mvn -pl AuthService spring-boot:run
mvn -pl ProductService spring-boot:run
# ... inventory / order / gateway
OPENAI_API_KEY=sk-... mvn -pl AiService spring-boot:run

Profiles

Each service ships application.yml plus application-docker.yml / application-k8s.yml:

  • local — everything on localhost (IntelliJ)
  • docker — container on host, reaches host via host.docker.internal
  • k8s — pod in Minikube, reaches host via host.minikube.internal

Configuration philosophy

Config is environment variables with sane defaults; secrets are never hard-coded. The OpenAI key is injected at runtime (env var locally, Kubernetes Secret in-cluster, Sealed Secret under GitOps).
