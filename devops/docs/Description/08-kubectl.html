08 — Deploying with Kubectl

The most explicit deployment path: build images into Minikube and apply raw Kubernetes manifests. Useful for understanding exactly what runs in the cluster before adding Helm/GitOps on top.

What gets created

For each service (devops/k8s/<Service>/):

  • Deployment — pod spec, image, probes (readinessProbe / livenessProbe on the health path)
  • Service — ClusterIP exposing the pod on port 80 → container port
  • ConfigMap — non-secret config (DB host, Redis host, Kafka brokers, Chroma URL, …)

Shared secrets (created once, out-of-band):

  • auth-service-jwt-keys — the RSA key pair (mounted into every pod at /app/keys)
  • auth-service-secret — DB credentials
  • ai-service-secret — optional OpenAI key

How pods reach host data stores

Pods are ClusterIP; MySQL/Redis/Kafka/Chroma run on the host. Pods reach them via host.minikube.internal (set in each ConfigMap), so the cluster stays stateless and the data stores stay on the host you manage.

One command for the whole platform

minikube start
OPENAI_API_KEY=sk-... ./devops/script/install.sh

install.sh is idempotent — it tears everything down first, then for each service:

  1. builds the JAR (mvn package) and a Docker image inside Minikube's Docker (no registry needed),
  2. creates the shared secrets,
  3. kubectl apply -f the ConfigMap + Deployment + Service,
  4. waits on kubectl rollout status.

Teardown (also idempotent, safe to alternate with install):

./devops/script/uninstall.sh

Per-service deploy

Each service has its own scripts, sharing a small paths.sh library:

./devops/script/InventoryService/minikube-deploy.sh
./devops/script/InventoryService/minikube-uninstall.sh

Accessing a service

kubectl port-forward svc/gateway-service 8088:80
kubectl get pods          # watch readiness
kubectl logs -l app=ai-service --tail=50

Why it matters (skills shown)

Core Kubernetes objects (Deployment/Service/ConfigMap/Secret), readiness/liveness probes, building images straight into Minikube's Docker daemon, and writing idempotent, re-runnable deploy scripts.
