10 — GitOps with Argo CD (+ Sealed Secrets)

Helm tells the cluster what to run, but a human still runs helm install. Argo CD closes the loop: Git becomes the single source of truth, and the cluster continuously reconciles itself to match.

The principle

git push ─► Git repo (Helm chart) ─► Argo CD detects drift (OutOfSync)
                                          │
                                          ▼
                          Argo CD: helm template ─► kubectl apply ─► cluster

Argo CD watches the repo. When the rendered chart differs from the live cluster, the app goes OutOfSync; on sync, Argo CD renders the Helm chart internally and applies the result. No one runs helm by hand — you change Git, the cluster follows.

What I set up

  • devops/argocd/install-argocd.sh — installs Argo CD (uses server-side apply to avoid the CRD metadata.annotations 256 KiB limit).
  • devops/argocd/applications/commerce-platform.application.yaml — an Application pointing at devops/helm/commerce-platform on branch master, with automated sync.
source:
  repoURL: https://github.com/.../cloud-ai-commerce-platform.git
  targetRevision: master
  path: devops/helm/commerce-platform
  helm:
    valueFiles: [values.yaml, values-sealed.yaml]
syncPolicy:
  automated: { prune: true, selfHeal: false }

The secrets problem — and Sealed Secrets

GitOps wants everything in Git, but you must never commit a plaintext API key. Solution: Bitnami Sealed Secrets.

plaintext key ──kubeseal──► ciphertext (values-sealed.yaml) ──git push──► Argo CD
                                                                             │ sync
                                                          controller decrypts ▼
                                                              Secret: ai-service-secret
  • The ciphertext is encrypted with the controller's public cert; only the in-cluster private key can decrypt it. It is safe to commit — even to a public repo.
  • Workflow:
devops/argocd/sealed-secrets/install-sealed-secrets.sh        # controller + kubeseal CLI
OPENAI_API_KEY=sk-... devops/argocd/sealed-secrets/seal-ai-openai-key.sh
git add devops/helm/commerce-platform/values-sealed.yaml && git commit && git push

Argo CD syncs the SealedSecret; the controller materializes the real ai-service-secret, which the AI service consumes via envFrom.

Lessons learned (real debugging)

  • CRD too large for client-side apply → switch to kubectl apply --server-side.
  • targetRevision: main vs master → Argo CD couldn't resolve the branch; matched it to the repo's default.
  • Manual vs GitOps conflict → while the auto-syncing Application exists, manual kubectl/helm changes get reverted; remove the Application first if you want manual control.

Why it matters (skills shown)

GitOps reconciliation model, Argo CD Application config, and secure secret management in Git via Sealed Secrets — the modern way to deploy to Kubernetes.
