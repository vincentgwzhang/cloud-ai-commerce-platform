11 — Observability with Prometheus & Grafana

Every service is observable by default: metrics, dashboards, and trace-correlated logs.

The pipeline

Spring Boot (Micrometer) ─► /actuator/prometheus ─► Prometheus (scrape) ─► Grafana (dashboards)
                          └─► OpenTelemetry trace IDs ─► structured logs (MDC)
  • Micrometer exposes JVM, HTTP, and custom business metrics on /actuator/prometheus.
  • Prometheus scrapes every service on an interval.
  • Grafana auto-provisions a "Commerce Platform Overview" dashboard (datasource + dashboard as code).

Two scrape modes

Mode How Prometheus reaches the apps
Local (IntelliJ) apps on the host → host.docker.internal:808x/actuator/prometheus
Minikube *-metrics NodePort services on the minikube Docker network

Minikube apps are ClusterIP, so a Docker-based Prometheus can't see them directly. The fix is a set of NodePort metrics services, applied separately from the app chart:

./devops/script/observability/minikube-metrics-apply.sh                          # create NodePorts (re-run after each cluster rebuild)
docker compose -f devops/script/docker-compose-observability-minikube.yml up -d  # Prometheus + Grafana + Chroma

Gotcha I hit: starting the compose without applying the NodePorts first shows every target DOWN in Grafana. It's not a port-forward issue — Prometheus simply has nothing to scrape yet.

What the dashboard shows

  • Service availability (up per job, red/green)
  • HTTP request rate and p95 latency per service
  • Auth: login success/failure, JVM heap
  • Product: cache hit/miss
  • Inventory: reservations, locks, Kafka consume/publish
  • Order: created/failed, event publish, Kafka failures
  • Gateway: request rate by route

Trace correlation

A request filter assigns/propagates an X-Request-Id, bridges the OpenTelemetry trace context into the logging MDC, and emits structured logs like:

... [requestId] [traceId] com.vincent... - message

So a single request can be followed across services in logs and traces.

Why it matters (skills shown)

The metrics → scrape → dashboard pipeline, dashboards/datasources as code, custom business metrics, and request tracing/log correlation — the three pillars of observability in practice.
