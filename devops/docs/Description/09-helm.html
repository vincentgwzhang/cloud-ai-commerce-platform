09 — Packaging & Deploying with Helm

The raw manifests from Kubectl are duplicated per service and hard to keep in sync. Helm collapses all six services into one parameterized chart.

The chart

devops/helm/commerce-platform/

Chart.yaml
values.yaml                # one place for every service's image/port/probes/deps
values-sealed.yaml         # Sealed Secrets ciphertext (GitOps; see Argo CD doc)
templates/
  _helpers.tpl             # shared labels / naming helpers
  <service>-deployment.yaml
  <service>-service.yaml
  <service>-configmap.yaml
  ai-service-sealedsecret.yaml   # value-gated, off by default

Each template is gated by {{- if .Values.services.<name>.enabled }} and pulls everything from values.yaml — image repo/tag, ports, probe timings, and shared dependency hosts (host.minikube.internal for MySQL/Redis/Kafka/Chroma).

From manifests to template

kubectl (static):

containerPort: 8082
image: inventory-service:1.0.0

Helm (templated):

containerPort: {{ .Values.services.inventory.containerPort }}
image: {{ include "commerce-platform.image" .Values.services.inventory.image }}

One chart, many environments — override with --set or a values file.

Lifecycle

# optional: produce a versioned .tgz artifact
./devops/helm/helm-package.sh        # helm lint + helm template + helm package

# install / upgrade (idempotent: runs helm-uninstall first, builds 6 images, then upgrade --install)
OPENAI_API_KEY=sk-... ./devops/helm/helm-install.sh

# remove the release (also cleans legacy kubectl leftovers)
./devops/helm/helm-uninstall.sh

Under the hood the install runs:

helm upgrade --install commerce-platform devops/helm/commerce-platform \
  --set services.ai.image.tag=1.0.0 ... --wait --timeout 10m

Verify the rendering without a cluster

helm lint devops/helm/commerce-platform
helm template commerce-platform devops/helm/commerce-platform

Why it matters (skills shown)

Helm templating and helpers, a single source of truth for multi-service config, release lifecycle (upgrade --install, rollback-ready revisions), and packaging a deployable artifact.
