06 — Gateway Service

A single HTTP entry point for the platform, built on Spring Cloud Gateway.

Port: 8088 · Stack: Spring Cloud Gateway (reactive)

What it does

Routes external traffic to the business services by path prefix:

Path prefix Backend (in-cluster)
/api/v1/products/** product-service:80
/api/inventory/** inventory-service:80
/api/orders/** order-service:80

Login stays on Auth (8080): clients obtain a JWT there, then call business APIs through the gateway with the Authorization: Bearer header.

Design decisions

  • Environment-agnostic routing. Upstream URIs are config-driven: localhost:808x locally, Kubernetes ClusterIP service names (product-service:80) in the cluster — the same code, different values.
  • One public surface. Clients learn a single host/port; internal topology can change freely behind it.

Why it matters (skills shown)

API gateway pattern, reactive Spring Cloud Gateway, and config-as-environment so one artifact runs unchanged from laptop to Kubernetes.
