07 — AI Service

The newest service: a conversational assistant and a Retrieval-Augmented Generation (RAG) engine over the product catalog.

Port: 8084 · Stack: Spring Boot, Redis, Kafka, MySQL · AI: OpenAI + ChromaDB

Capabilities

Endpoint What
POST /api/v1/ai/chat Chat turn with short-term memory
GET /api/v1/ai/conversation/{id} Read a conversation
DELETE /api/v1/ai/conversation/{id} Forget a conversation
POST /api/v1/ai/ask Ask a natural-language question answered from real product data (RAG)

How RAG is built

Product service ──(Kafka: product-created/updated/deleted)──► AI service
                                                                  │  embed (OpenAI)
                                                                  ▼
                                                            ChromaDB (vector replica)

ask("a quiet laptop under €1000") ─► embed query ─► similarity search (top-k)
                                   ─► build grounded prompt ─► OpenAI chat ─► answer + sources

Design decisions

  • Service boundaries kept clean. Product data stays owned by Product service. AI keeps an eventually-consistent vector replica, synchronized via Kafka product events — no cross-service DB reads.
  • Everything swappable behind interfaces. EmbeddingProvider, ProductVectorStore, and LlmClient are interfaces; the OpenAI + ChromaDB implementations can be replaced without touching the RAG pipeline.
  • Conversation memory in Redis (per user → conversation → messages) with sliding TTL, so chat has context but storage self-expires.
  • Resilience. External-AI failures map to a dedicated exception → clean 503; Kafka sync uses retries + dedup; Redis/Chroma are reached lazily so the app still boots if they're down.
  • Secrets stay out of Git. The OpenAI key is injected at runtime and, under GitOps, committed only as Sealed Secrets ciphertext.

Why it matters (skills shown)

Practical LLM integration (embeddings, vector search, prompt grounding), event-driven data replication with correct boundaries, and pragmatic resilience around third-party APIs.
